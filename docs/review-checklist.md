# 工作台验收清单（准备稿）

本清单表达产品验收标准。官方逐版本验收后方可收录；审核服务和自动化尚未接入。尚缺宿主能力的项目应列为阻塞或限制，不标记通过。

## 1. 投稿材料

- [ ] 场景、名称、标识、版本和作者信息清楚。
- [ ] GitHub 渠道提供作者仓库及完整 commit SHA；产品内渠道提供固定版本包及可追踪的提交记录，不强制要求 GitHub 仓库。
- [ ] 产品内提交完成联系邮箱校验；具体校验方式与服务待第二期实现，邮箱不写入公开目录。
- [ ] 提供安装步骤、可检查的源码和实际验证的 DSH Desktop 版本；安装包可追溯到提交版本，并提供 SHA-256。
- [ ] 依赖、权限、外部服务、授权及限制说明完整，不含凭据或私人业务数据。
- [ ] 本次变更、验证步骤和证据可复现。

## 2. 界面与会话

- [ ] 保留 DSH 的市场、工作台切换、设置等公共入口。
- [ ] 保留宿主原生 Agent 对话能力；同一前台会话仅有一个原生输入入口，不以跳到通用聊天页冒充工作台内对话。
- [ ] 业务面板允许自行设计，不强制采用任务区、资料区、成果区等固定分区；依赖的宿主接口明确。
- [ ] 一个工作台支持多个会话，每个会话最多关联一个工作台；会话使用其所属工作台的能力，不混用其他工作台的工具或提示词。
- [ ] 同时只展示一个前台工作台；切换后显示目标工作台及对应会话，不停止已有后台任务。
- [ ] 点击具体会话时打开该会话并唤起已安装的所属工作台；所属工作台已卸载时不自动唤起或安装。
- [ ] 新建或切换所属会话时保留工作台业务界面；会话输入草稿独立，业务状态不被意外清除。
- [ ] 侧边栏固定入口和拖动排序与宿主规则一致。
- [ ] 项目归属沿用 DSH Desktop 规则；工作台与项目不混为一个概念。
- [ ] 默认 preset 及切换沿用现有 DSH Desktop 规则。

## 3. 生命周期与兼容

- [ ] 无会话时的初始化行为有说明，区分空状态绑定引导与在默认工作区新建会话，说明默认来源及当前限制。
- [ ] 进入已有工作台能恢复最近会话；点击具体会话优先打开被点击的会话。
- [ ] 安装、移除、切换及升级不意外删除用户会话、资料或成果，说明移除后的实际行为。
- [ ] 宿主升级兼容范围与工作台自身版本更新分别说明；不声明未经验证的任意版本兼容。
- [ ] 核心功能不依赖未声明的宿主修改或临时适配；如需适配，明确步骤、版本和支持边界。
- [ ] 若提供个性化布局或恢复默认，说明保存及重置范围，不要求所有工作台实现通用布局编辑器。

## 4. 验收记录

审核者记录本次工作台版本、源码 commit 或固定包提交标识、包校验值、宿主版本、验证结果和未解决问题。结论使用“通过 / 待补充 / 未通过”，并写明理由。修改源码或发布新版本后重新验收。

目录收录只对已验收版本有效；最终在线发布方式及审核自动化仍待实现。
