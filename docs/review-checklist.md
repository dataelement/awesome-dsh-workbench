# 维护者审核清单

自动探测不执行插件，不能验证真实业务行为。维护者在 PR 中记录审核的 head SHA、工作台版本、source commit、包校验值、实测环境、结果和未解决问题；结论为「通过 / 待补充 / 未通过」。作者的自查不是维护者验收。

## 通用

- [ ] PR 类型和范围正确，作者/仓库关联及修改理由可信，不混入其他条目。
- [ ] 最新提交的 Catalog CI 与 Trusted catalog probe 均通过，网络未验证不能当作通过。
- [ ] 描述、图片与源码功能相符，无营销夸大、敏感信息或不明授权素材。
- [ ] 权限、外部服务、费用、安装/卸载步骤、支持平台和未验证项明确。
- [ ] 工作台 ID 保持稳定；更换仓库或 ID 的迁移影响单独评估。

## 首次收录或安装来源变更

- [ ] 审查选中的 npm / Release / 源码来源；包内 manifest 与 package.json 版本一致，源码开发版本可能领先正式包版本。
- [ ] 在记录的 Desktop/系统版本上实际安装、打开、重启后加载；不把 CI 成功作为运行验证。
- [ ] 无会话时业务面板可用；原生新会话不自动绑定；显式创建/恢复归属正确。
- [ ] 切换工作台后保留资料、会话和草稿，不停止无关后台任务，不遮挡公共入口。
- [ ] 安装失败、取消及卸载不破坏原数据；清除数据必须是独立明确操作。
- [ ] 目标平台差异得到验证，未验证平台明确列出。

## 文案、图片或下架

文案/图片修改仍需核对真实性、授权与固定版本；普通发版自动探测，不宣称逐版本人工验收；展示信息 PR 按实际变化审核。下架必须说明原因、范围、作者反馈和恢复条件；不会自动卸载用户已安装的工作台或删除数据。

## 合并与发布

审批后新增提交需要重新确认。合并检查通过只代表获准进入目录；维护者还应核对发布工作流、线上 publication.json 和 catalog.json 的 commit/校验值。发布失败时保留上一完整目录，按[运行手册](operations.md)处理。
